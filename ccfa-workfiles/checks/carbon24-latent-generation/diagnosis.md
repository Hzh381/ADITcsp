# Carbon-24：基于完整日志的结论与修复方案

日期：2026-11-03。代码基线：6d11b69。已核对用户提供的五个文件：11 个训练任务、11 个评测任务、22,330 条逐目标记录。全部 Match@20 与逐目标结果一致，三份 CSV 的训练损失相互一致。统计保存在 log_analysis.json；先前合成代码检查保存在 mechanics.json。

## 明确结论

两阶段方案可以继续使用。当前 HiLo 路径的问题集中在第二阶段的结构族覆盖：能生成有效晶体，但反复落在少数目标可匹配的区域。现有数据不支持把“数据太少、HiLo 后验更不高斯、KL 太小”当作已确认的主因，也不支持继续增加去噪器深度来解决问题。

重建时编码器已看到真实结构；成分生成时必须覆盖同一成分下的多种结构。高重建率不会自动变成高生成命中率。

## 日志直接支持的判断

| 指标 | HiLoVAE + DiT | 标准 VAE + DiT |
|---|---:|---:|
| 生成 Match@20 | 17.29% | 60.00% |
| 有效结构率 | 97.03% | 97.15% |
| C6 Match@20 | 62/705 | 343/705 |
| C8 Match@20 | 23/526 | 311/526 |
| C6 Match@1 | 61/705 | 183/705 |
| VAE 最后验证 KL（未加权） | 45.75 | 45.14 |
| DiT 最后训练/验证主损失 | 1.776/1.815 | 2.040/2.085 |

1. 六种 HiLo 生成模型共同命中的 C6 目标为同一批 61 个；六者命中并集也只有 66 个。普通 HiLo+DiT 中，61 个 C6 目标每个都被 20 个候选匹配，643 个目标则一次也没有匹配。候选在同一覆盖区域内变化，未有效覆盖其他结构族；这不等于已经做过生成晶体之间的结构去重。
2. 按本地测试数据的目标空间群标签对应，这 61 个目标属于空间群 51（22 个）与 63（39 个）；295 个 C6 空间群 12 目标，HiLo+DiT 只命中 1 个，标准 VAE+DiT 命中 187 个。标签描述的是被命中的目标，不能据此断言生成晶体的实际空间群。
3. C6/C8 贡献 569 个额外失败，占两种 DiT 总命中差距 867 个的 65.6%；它们又是训练样本最多的组。稀有大 N 样本不足不能解释主要差距。
4. HiLo+DiT、DiverseDiT 等训练与验证主损失接近，学习率已降至约 1e-6，训练 350–650 epoch 后仍在相同覆盖区域。没有证据认为只需继续堆 epoch 或加深网络。
5. HiLo 验证 KL 与标准几乎相同；KL 相似不能证明两种聚合后验形状相同，但足以撤回“HiLo 一定是 KL 更失控”的说法。HiLo 的 KL 项在其最终总验证 loss 中占约 29%，盲目把 beta 提高 10–100 倍没有依据。
6. 标准 VAE 的验证角度损失为 0.763、晶格长度损失为 0.102，HiLo 分别约 9.58e-5、4.01e-5。标准 VAE 60% 生成匹配率伴随明显重建缺陷，不能把它解释为可靠的高精度结构恢复。
7. 普通两种 DiT 的 20 候选结果中，均没有目标获得 normalized RMS < 0.1 的候选。mean_best_rms 又排除匹配失败目标。当前 60% 应理解为既有容差下的匹配成绩。

## 优先修复共同生成路径

最强代码证据是源分布和训练模式不一致；它们造成多少个百分点的差距尚无法仅凭日志定量。

- src/models/interpolants/flow_matching.py:46：沿原子维中心化噪声时包含 padding。训练混合长度，测试同成分无 padding；有效噪声均值方差不同。潜变量的全局均值本来可能携带晶格信息，零均值源也减少了这部分随机自由度。
- src/models/ldm_module.py:41：只在构造时调用 autoencoder.eval；父模型 train 会重新开启其 dropout。合成验证已复现，服务器影响取决于实际 dropout 配置。
- src/models/ldm_module.py:152：self-conditioning 的第一次预测在训练模式下生成，正式采样却使用 eval 和 CFG 后的递归预测，输入分布不同。其贡献是合理机制推断，尚未由这些日志单独测出。
- src/models/components/posterior_mmd.py:47：混合长度 MMD 仅比较平均 latent，丢掉原子关系；带宽还对平方距离重复平方。日志中最后 MMD 加权项约 0.000352，只有 x_loss=1.822 的约 0.019%，且约束特征不完整。隐藏层 diversity 不等于输出结构族覆盖。继续启用这些项没有解决共同路径。

## 一套有成本上限的方案

保留已经训练好的 HiLoVAE，第二阶段采用普通 DiT，从 carbon24_dit 现有最佳验证 checkpoint（日志约第 250 epoch）初始化模型权重，执行一次修复后微调。

1. VAE 始终 eval 且冻结参数，保留 posterior.sample。实现：

```python
def train(self, mode=True):
    super().train(mode)
    self.autoencoder.eval()
    return self
```

2. 训练和所有采样入口统一使用独立高斯，取消原子维度减均值，padding 仅置零：

```python
z0 = torch.randn(B, Nmax, D, device=device)
z0 = z0 * mask[..., None]
```

不得只修改旧模型的测试噪声；微调时一起使用新源分布。不得删除每个 posterior 自己的均值。

3. self_condition=False，训练/采样都输入零 self-conditioning；正式生成 CFG=1，直接使用条件分支。普通 DiT、无 OT/MMD/diversity，保持当前网络规模，先消除已知或可避免的反馈与外推因素。

4. 若使用通道标准化，只做一次训练集统计，使用有效原子 token，保存 m、s 作为 checkpoint buffer；训练目标为 (z-m)/s，解码前恢复 z*s+m。为复用原始权重，可在 denoiser 输入/输出处放逆变换和正变换的适配层，避免直接把预训练模型的原始 latent 输入改成不同尺度。标准化不是已证实主因的修复，预算最紧时可省略这一项。

5. 重新建立优化器和调度器，学习率 1e-5，batch=32，最多 50 epoch（约 9,500 更新，原普通 HiLo+DiT 的约 14% 更新量）。加载模型权重而不直接恢复已降至 1.56e-6 的旧优化器状态。这个上限是成本控制建议，不能保证 50 epoch 完成分布迁移。

6. 每 10 epoch 用同一小验证子集、K=20、固定随机种子跑完整生成，按 Match@20 选择此次微调 checkpoint。这是一次训练的模型选择，不再安排方法消融或额外扫描。训练结束后按同一协议评测。

改变噪声源与反馈设置后，原 checkpoint 只是初始化，不能沿用旧训练定义宣称直接提升。若这次限定预算修复无有效收益，停止继续投资当前 HiLo latent 生成路线，使用现有标准 VAE+DiT 的 60% 结果作为当前工程基线；不再追加 VAE 重训、beta 网格搜索或新去噪器。
