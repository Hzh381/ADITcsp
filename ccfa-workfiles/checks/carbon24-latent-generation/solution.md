# Carbon-24 两阶段生成：结论与实施方案

分析日期：2026-11-03。证据来自仓库代码、本地 Carbon-24 数据副本，以及 `D:\HZH\DownLoad` 中统一导出的训练曲线、测试摘要和逐目标结果。测试统一为 2030 个目标、每目标 20 个候选、100 步、CFG=2。

## 决策

两阶段生成用于晶体候选预测是可行的，但目前“标准 VAE + 标准 DiT”已经是有效路线，当前“直接生成 HiLoVAE 原始潜变量”的路线不可继续作为主线。

工程方案采用：

1. 标准 VAE + 标准 DiT 负责生成多峰候选，因为它实际覆盖更多目标。
2. HiLoVAE 保留为结构精修器/高保真编码器，不再直接作为第二阶段生成目标。
3. 一次修复训练与采样一致性缺陷，并使用 best checkpoint。
4. 先让粗生成覆盖正确结构家族，再由 HiLo 模块修正晶格和局域几何。

这不是三套并行实验。诊断已经完成，后续只需要实现一条新管线并用验证集验收一次。

## 现有结果说明了什么

| 路线 | 生成 Match@20 | 重建 Match@20 | 结论 |
|---|---:|---:|---|
| HiLoVAE + CoDeMDT decoder=6 | 15.81% | 97.54% | HiLo 解码器在收到真实结构后验时很强 |
| HiLoVAE + 标准 DiT | 17.29% | 97.54% | 第二阶段没有通向正确的 HiLo 潜变量区域 |
| HiLoVAE + DiverseDiT | 17.34% | 97.54% | 只增加多样性模块没有改变覆盖 |
| HiLoVAE + OT-only | 18.57% | 97.54% | OT 配对没有改变生成潜变量区域 |
| HiLoVAE + MMD-only | 17.19% | 97.54% | 当前对齐目标没有解决覆盖 |
| 标准 VAE + CoDeMDT decoder=6 | 58.92% | 34.58% | 同一个第二阶段架构换成标准潜变量后恢复覆盖 |
| 标准 VAE + 标准 DiT | 60.00% | 34.58% | 当前最佳实际路线 |

因此，不能再把主要原因归到 CoDeMDT、DiverseDiT、MMD 或 OTFM 的局部网络设计。VAE 潜变量接口的选择远大于这些改动。

### 五种 HiLo 第二阶段模型命中高度重合

与 HiLo CoDeMDT decoder=6 的匹配目标集合相比：

- 标准 DiT 的 Jaccard 重合为 0.836；
- MMD-only 为 0.866；
- DiverseDiT 为 0.834；
- OT-only 为 0.794；
- 所有 HiLo CoDeMDT decoder=6 的 321 个命中目标，都包含在 HiLoVAE 的 1980 个可重建目标中。

不同生成架构反复命中的是同一组结构。这说明主要失败发生在所有模型共享的潜变量、采样和训练路径，而不是某个新增模块。

### 候选并不是“K 还不够”，而是按目标全部命中或全部失败

以 HiLoVAE + 标准 DiT 为例：

- 1679/2030 个目标，20 个候选全部不匹配；
- 144 个目标，20 个候选全部匹配；
- 只有 207 个目标处于中间状态。

HiLo CoDeMDT decoder=6 更极端：1709 个目标没有一个候选匹配，151 个目标 20 个全部匹配。

标准 VAE + 标准 DiT 则是：

- 812 个目标全部失败；
- 20 个目标全部命中；
- 1198 个目标有部分候选命中。

HiLo 生成器在给定成分后主要落入单一结构盆地。目标若在这个盆地内，所有候选都匹配；目标不在其中，增加到更多 K 也基本无效。标准 VAE 的候选分布覆盖多个盆地，所以部分命中的模式更多。

### 总体落后主要来自 C6 和 C8

测试集中 C6 有 705 个、C8 有 526 个，共 1231 个，占 60.6%。

| 8 | 526 | 4.4% | 59.1% |

HiLo 在 C20–C24 反而更好，但这些结构很少。它的问题集中在训练样本最多的 C6/C8，主流碳结构目标的覆盖被单一盆地吞掉。以两条标准 DiT 路线比较，整体差距 867 个目标中，C6/C8 差距为 569 个，约占 66%。这与“数据总量太小导致学不会”不一致。

### 重建指标不能当作生成上限

HiLoVAE 的 97.54% 是给定真实测试结构后验后的重建率。第二阶段并不知道测试结构，只看到成分。它学习的是同一成分下所有结构的聚合分布。高保真后验可解码，不等于从成分先验能找到每一种多晶型。

`mean_best_rms` 只对匹配成功的目标求均值。HiLo 的低 RMS 来自不同目标集合，不能补偿 84% 目标完全没有匹配候选的问题。

## 主要原因判断

### 1. HiLoVAE 的潜变量高保真，但当前生成路径发生模式覆盖坍塌

这是现有数据直接支持的结论。HiLo 生成的候选在 20 次独立采样后仍表现为全命中或全失败，而 HiLo 重建证明解码器有能力输出准确结构。瓶颈在“如何生成正确盆地的潜变量”，不在 HiLo 解码精度。

标准 VAE 的重建只有 34.58%，但它的潜变量更容易由 DiT 覆盖多个结构。这说明重建精度与可生成性之间存在取舍。当前 VAE 把大量能力用于精确几何，第二阶段直接学习其原始后验，导致结构覆盖变窄。

### 2. 第二阶段训练目标没有直接监控候选覆盖

验证只计算真实 posterior 加噪后的去噪误差，最终却用它选择生成模型。HiLo 几个模型的验证损失低于标准 VAE 模型，但测试 Match@20 只有 16%–19%，说明不同潜空间的 loss 数值不可比较，也不能代表完整采样质量。

### 3. 训练和生成存在四个共同一致性缺陷

代码中的缺陷会进一步收窄 HiLo 生成分布：

- `LatentDiffusionLitModule` 没有重写 `train()`，父模型进入训练模式时会重新开启冻结 VAE 的 dropout。第二阶段学习的后验与测试、重建时的后验不一致。
- 噪声中心化使用 padding 后的整体长度。混合原子数训练和单一成分测试的噪声方差不同。
- 第二阶段直接使用未标准化的 8 维 token 后验，没有让生成先验与每个 VAE 实际 latent 尺度匹配。
- 当前 MMD 在混合长度 batch 中只比较每个结构的平均 8 维向量，带宽定义也对尺度敏感，不能有效约束完整原子潜变量。

现有五条 HiLo 路线的匹配高度重合，说明这些共同因素必须在最终方案中修复；单独更换生成器不会改变结果。

### 4. 条件只给出原子数，存在结构歧义

Carbon-24 只有 C6、C8、…、C24 共 10 种成分条件，空间群在训练和测试中都被置零。同一成分下存在多个结构时，模型无法知道用户希望哪一个。这解释了为什么 20 个候选仍可能覆盖不到个别多晶型，但不能解释 HiLo 在 C6/C8 上 4%–9% 的低覆盖，因为标准 VAE 在同一条件下达到约 50%–60%。

## 推荐实施方案

### 主方案：标准 VAE 发现结构，HiLo 精修几何

生成路径：

```text
composition c
  -> standard DiT, fixed best checkpoint
  -> standard VAE latent z_s
  -> standard VAE decoder
  -> coarse crystal X_coarse
  -> HiLo conditioned refiner R(X_coarse, c)
  -> refined candidates
```

标准 VAE 保留 60% 的结构盆地覆盖。HiLo refiner 从粗结构的原子类型、分数坐标和晶格开始，做局域几何与晶格修正。接口使用结构而不是直接把一个 VAE latent 投到另一个 VAE latent，因为两个编码器没有天然可比的坐标语义。

refiner 可以直接使用现有 HiLo 编解码器作为骨架，训练输入为：

- 训练集中真实结构；
- 对原子坐标加小幅周期位移；
- 对晶格长度、角度加受控扰动；
- 对部分原子类型或局部邻域做遮蔽。

目标仍是原训练结构。这样它学习的是“把标准 VAE 的粗糙输出搬回合理晶体流形”，不会改变测试集的条件设定。此阶段只在验证集使用，最终测试一次。

### 快速可交付方案

如果目标是尽快得到可用结果，先采用标准 VAE + 标准 DiT：

- 固定使用 `standard_vae_standard_dit` 的 best checkpoint；
- 生成 20 个候选；
- 用几何有效性、体积/密度先验、局部冲突能量和周期性距离做排序；
- 对排名靠前的少量候选做能量或几何松弛。

这条路线已经达到 60% Match@20、97.15% 候选结构有效率、100% 成分正确率，可以立即作为稳定基线。CoDeMDT decoder=6 与它的匹配只差约 1 个百分点，不值得继续优化第二阶段层数。

### 必须同步修复的代码

只修复以下关键路径，不增加 architecture sweep：

1. **永久保持 VAE eval**

```python
def train(self, mode: bool = True):
    super().train(mode)
    self.autoencoder.eval()
    return self
```

在 `sample_and_decode` 和所有测试入口也应显式调用 `autoencoder.eval()`。

2. **统一噪声定义**

训练和采样使用同一套独立高斯源。推荐直接用 `randn_like`，只在有效 token mask 内使用，padding 置零。若保留中心化，必须按有效 mask 中心化，并让训练与采样完全一致；修改后需要重训第二阶段。

3. **生成前反标准化**

在训练集有效 token 上记录每通道均值和方差，第二阶段优化标准化 latent。最终解码前恢复原始尺度。这项改动必须与第二阶段重训一起完成，不能只改测试。

4. **使用 best checkpoint**

训练日志显示所有第二阶段模型在末尾若干 epoch 的验证损失都高于自己的最佳点。生成摘要又没有记录 checkpoint 路径，无法排除使用了 `last.ckpt`。最终交付必须固定 best checkpoint，并在摘要中保存 VAE 与 DiT checkpoint hash。

5. **修复 MMD 后再使用**

当前混合长度 MMD 丢弃逐原子结构信息，且 RBF 带宽重复平方。若最终方案需要分布对齐，应把样本按成分/原子数分组，比较完整有效 token 序列；否则直接删掉这项损失，避免它给出虚假的安全感。

## 一次性验收，不需要模型穷举

实现上述管线后，只做一次固定协议验收：

1. 固定验证集目标、随机种子、候选数 K=20；不要再用测试集做设计选择。
2. 主结果比较 `standard VAE + standard DiT` 与 `standard generation + HiLo refinement`。
3. 同时报告：
   - Match@20；
   - 所有匹配目标集合之外的候选和 RMS；
   - 0/20 全失败目标和 20/20 全命中目标数；
   - 候选有效率、成分正确率、晶格/角度误差；
   - 按 C6/C8、C10–C18、C20–C24 分层结果。

验收重点不是“refiner 是否再提高几个点”，而是先确认 HiLo 精修没有摧毁标准 VAE 已覆盖的结构盆地，然后再看 RMS 和有效率是否提升。若标准生成 + HiLo 精修在验证集保持 60% 左右覆盖，同时降低晶格/角度误差，就可以进入最终测试。

不要再并行训练 CoDeMDT、DiverseDiT、OT、MMD 的更多变体。现有数据已经表明，这些修改在错误潜变量目标下只会得到同一组约 16%–19% 的命中目标。只有当新管线仍显示出独立的结构覆盖瓶颈，才需要改条件或增加结构先验。

## 最终判断

两阶段晶体生成可行。当前失败的原因是采用了“高重建精度的 HiLo 原始潜变量”作为直接生成目标，而生成阶段只覆盖了其中极窄的结构盆地。把标准 VAE 用于候选发现、把 HiLo 用于精修，是同时利用两套模型优势的最短路线。

若必须保留严格的端到端两阶段结构，应重训一个“生成友好”的 HiLo VAE：加强 KL/先验对齐、使用标准化潜变量、训练周期感知几何误差，并增加 coarse decoder + 自条件 HiLo refinement。这条路线的成本高于主方案的 incremental refiner，不应作为当前首要选择。
